# Marvel Snap Deck Builder AI

เครื่องมือจัดเด็ค Marvel Snap ที่ทำงานจากการ์ดที่คุณมีจริง แปลภาษาไทยทั้งการ์ดและ Location ครบ พร้อมระบบอัปเดตข้อมูล/แพตช์แบบไม่ต้องมี backend

## 🔗 ใช้งานได้เลยที่นี่

**[bennett-workspace.github.io/marvelsnap-ai-assistant/marvel-snap-deck-builder.html](https://bennett-workspace.github.io/marvelsnap-ai-assistant/marvel-snap-deck-builder.html)**

เปิดลิงก์นี้ในเบราว์เซอร์ได้เลย ไม่ต้องดาวน์โหลดหรือติดตั้งอะไร — ข้อมูล (การ์ดที่คุณมี, เด็คที่บันทึกไว้) จะถูกเก็บไว้ในเบราว์เซอร์ของคุณเองเท่านั้น (localStorage/IndexedDB) ไม่ส่งขึ้นเซิร์ฟเวอร์ไหนทั้งนั้น

## ✨ ฟีเจอร์หลัก

- **ฐานข้อมูลการ์ด 494 ใบ** — ครบทุกใบ พร้อมคำอธิบายความสามารถแปลไทยแบบธรรมชาติ (ไม่ใช่แปลตรงตัว), รูปภาพ Variant ทุกแบบ, ตัวกรองตาม Series/Archetype/กลไก
- **ประวัติการปรับสมดุล (บัฟ/เนิร์ฟ)** ต่อการ์ด — ย้อนดูได้ว่าการ์ดแต่ละใบเคยถูกปรับอะไรมาบ้าง พร้อม badge "▲ บัฟ / ▼ เนิร์ฟ / NEW" บนการ์ดที่เพิ่งเปลี่ยนใน 21 วันล่าสุด
- **เด็คแนะนำอัจฉริยะ** — วิเคราะห์จากการ์ดที่คุณมีจริง แยกชัดเจนระหว่าง "สร้างได้เลยตอนนี้" กับ "ขาดอีกกี่ใบ" ไม่ยัดการ์ดสุ่มๆ มาให้ครบ 12 ใบ
- **คลังเด็ค (Deck Library) 77 เด็ค** — ทั้งจากเมตาจริง (Cube/Win Rate จริงจาก Marvel Snap Zone) และเด็คมือใหม่ Pool 1-3 ที่คัดมาเอง มีตัวกรองค้นหา + ปุ่มโค้ดลงเกม
- **เมตาปัจจุบัน** — ตารางเมตารายสัปดาห์แยกตาม Tier พร้อมลิงก์แหล่งข้อมูลจริงทุกจุด และรายการการ์ดที่กำลังจะเข้าในซีซั่นนี้
- **ร้านค้า** — bundle ที่ขายอยู่ตอนนี้ / กำลังจะเข้า / จบไปแล้ว พร้อมราคา ช่วงวันที่ ความคุ้มค่า และของที่ได้ในแต่ละชุด
- **แถบอัปเดต** บนแดชบอร์ด — สรุปว่ามีอะไรเปลี่ยนในเกมบ้าง (ซีซั่นใหม่, การ์ดใหม่, OTA ล่าสุด, การ์ดที่กำลังจะมา) กดไปหน้าที่เกี่ยวข้องได้เลย
- **ซิงค์คอลเลกชันจากเกม** — อ่านการ์ดที่คุณมีจริงจากไฟล์ที่เกมเขียนไว้ในเครื่อง ไม่ต้องกดเลือกทีละใบ (ดู [ข้อจำกัด](#-ซิงค์คอลเลกชัน) ด้านล่าง)
- **Locations 184 ที่, Series, Variants, Variant Artists** — ฐานข้อมูลแยกหมวดครบ
- **ระบบอัปเดต Patch ในตัว** — กดปุ่มเดียวอัปเดตข้อมูลใหม่ (ค่าพลัง, การ์ดใหม่, เมตา, ร้านค้า) โดยไม่ต้องโหลดไฟล์ใหม่ทั้งไฟล์ พร้อมแจ้งเตือนอัตโนมัติเมื่อมีแพตช์ใหม่ และย้อนกลับเวอร์ชันได้หลายขั้นถ้าแพตช์มีปัญหา

ทุกอนิเมชันในแอปปิดอัตโนมัติถ้าระบบปฏิบัติการตั้งค่า **ลดการเคลื่อนไหว** (`prefers-reduced-motion`) ไว้

## 🛒 ข้อจำกัดของข้อมูลร้านค้า

ข้อมูล bundle เป็น **สแนปช็อต** ที่ดึงมา ณ วันที่ระบุไว้บนหน้า ไม่ใช่ข้อมูลสด — สถานะ "ขายอยู่ / กำลังจะเข้า / จบแล้ว" คำนวณจากช่วงวันที่ของแต่ละ bundle เทียบกับวันนี้ ถ้าสแนปช็อตเก่าเกิน 10 วันแอปจะขึ้นเตือนให้เห็นชัดเจน

**ตัวเลขความคุ้มค่าเชื่อได้ไม่เต็มร้อย** — ปัจจุบัน 18 จาก 21 bundle มีผลรวมมูลค่าของแต่ละชิ้นไม่ตรงกับยอดรวมที่แหล่งข้อมูลประกาศไว้เอง (บางใบต่างกันหลายพัน gold) แอปจะติดป้าย **"ไม่ครบ"** บอกตรงๆ เมื่อเจอกรณีแบบนี้ แต่เปอร์เซ็นต์ความคุ้มก็คำนวณจากยอดรวมชุดเดียวกัน จึงควรใช้เป็นตัวเลขอ้างอิงคร่าวๆ เท่านั้น ถ้าจะซื้อจริงให้เช็คในเกมอีกครั้ง

## 🔄 ซิงค์คอลเลกชัน

กดปุ่ม **🔄 Sync your collection** มุมขวาบน แอปจะอ่านไฟล์ที่เกมเขียนไว้ในเครื่องแล้วติ๊กการ์ดที่คุณมีให้อัตโนมัติ

- **ใช้ได้เฉพาะเครื่อง PC ที่เล่นผ่าน Steam** เท่านั้น เพราะอ่านไฟล์แคชที่เกมเวอร์ชัน Steam เขียนไว้บนเครื่องโดยเฉพาะ — เล่นผ่านมือถือหรือแพลตฟอร์มอื่นให้ใช้ "นำเข้าคอลเลกชัน" ในหน้าตั้งค่าแทน
- ทุกอย่างอ่านในเบราว์เซอร์ล้วนๆ ไม่มีการส่งข้อมูลออกไปไหน
- ซิงค์แต่ละครั้งจะ **แทนที่** คอลเลกชันเดิมทั้งหมด ไม่ใช่รวมกัน — สลับบัญชีเกมแล้วซิงค์ใหม่จึงได้ข้อมูลของบัญชีนั้นตรงๆ
- อยากให้ซิงค์ได้ในคลิกเดียวไม่ต้องเลือกไฟล์ทุกครั้ง ติดตั้ง extension ใน [`extension/`](extension/) ได้ (Chrome/Edge)

## 🧩 ระบบอัปเดตข้อมูล (ไม่มี backend)

ตัวแอปเป็นไฟล์ HTML เดียวโหลดจาก GitHub Pages — แต่ **ข้อมูล** (ค่าพลังการ์ด, เมตา, เด็คตัวอย่าง, ร้านค้า) แยกเก็บใน repo นี้ แล้วให้แอปดึงมาอัปเดตเองได้แบบ diff-only (ไม่โหลดข้อมูลทั้งก้อนใหม่ทุกครั้ง) ผ่าน [raw.githubusercontent.com](https://docs.github.com/en/repositories/working-with-files/using-files/viewing-a-file) ซึ่งรองรับ CORS โดยไม่ต้องมี backend ใดๆ

### โครงสร้าง repo

- `marvel-snap-deck-builder.html` — ตัวแอปหลัก (โฮสต์ผ่าน GitHub Pages)
- `manifest.json` — รายการเวอร์ชัน patch ทั้งหมด พร้อม URL และ SHA-256 hash สำหรับตรวจสอบความถูกต้อง
- `patches/{version}.json` — ไฟล์ patch แต่ละเวอร์ชัน เป็นชุดคำสั่ง [JSON Patch](https://datatracker.ietf.org/doc/html/rfc6902) (RFC 6902) แบบ `add` / `replace` / `remove` แก้เฉพาะจุดที่เปลี่ยน ไม่ใช่แทนที่ข้อมูลทั้งหมด — ไฟล์เลยเล็กแม้ฐานข้อมูลการ์ด/เด็คจะโตขึ้นเรื่อยๆ
- `verify-manifest.js` — ตรวจว่า manifest ตรงกับไฟล์ patch จริง **ต้องรันก่อน commit ทุกครั้งที่แตะ manifest**
- `scripts/` — สคริปต์สร้าง patch และเทส (`node --test` ใช้ตัวรันในตัวของ Node ไม่มี dependency ให้ติดตั้ง)
  - `scripts/patch-tools/current-state.js` — รวม baseline + patch ทั้งหมดเป็นสถานะปัจจุบันจริง ใช้ตรวจก่อนสร้าง patch ใหม่ทุกครั้ง
  - `scripts/patch-tools/build-test-html.js` — สร้างไฟล์ทดสอบที่ชี้ระบบอัปเดตไปที่ local server แทน GitHub จริง
- `extension/` — Chrome/Edge extension สำหรับซิงค์คอลเลกชันแบบคลิกเดียว
- `docs/PATCH_UPDATE_PLAYBOOK.md` — คู่มือ/master prompt ทุกขั้นตอนของการออก patch ใหม่ ใช้เปิดเป็นบริบทตั้งต้นได้ทุกครั้ง
- `docs/superpowers/` — spec และ implementation plan ของฟีเจอร์ที่ทำเป็นชุดใหญ่

### ความปลอดภัยของข้อมูล

- ตรวจ SHA-256 ก่อนติดตั้งทุกครั้ง — ถ้า hash ไม่ตรง (ไฟล์เสียหาย/ถูกแก้) จะยกเลิกทันที
- ตรวจ schema version ก่อนติดตั้ง — patch ที่เขียนมาสำหรับแอปเวอร์ชันใหม่กว่าจะถูกพักไว้ ไม่ทำให้ข้อมูลพัง
- เก็บ snapshot ย้อนหลังได้สูงสุด 10 เวอร์ชันใน IndexedDB — กด **ย้อนกลับ** ได้ทุกเมื่อถ้า patch มีปัญหา รวมถึงย้อนกลับไปข้อมูลตั้งต้นในไฟล์ได้เลย

### เวอร์ชัน

รูปแบบ `YYYY.MM.DD.NNN` (วันที่ + เลขลำดับ) เรียงจากน้อยไปมากเสมอ เทียบด้วย string ธรรมดาก็รู้ว่าอันไหนใหม่กว่า

### ⚠️ เรื่อง line ending — สำคัญมาก

`manifest.json` และ `patches/*.json` ถูกตรึงเป็น **LF** ไว้ใน `.gitattributes` ห้ามแก้

บน Windows `core.autocrlf=true` จะเขียนไฟล์ที่ checkout ออกมาเป็น CRLF ซึ่ง **ไบต์ไม่เหมือนกับที่ GitHub เสิร์ฟให้ client** ถ้าไปคำนวณ hash จากไฟล์ในเครื่องแทนที่จะเป็นไฟล์ที่ commit ไว้ hash จะผิดโดยไม่มีอะไรเตือน แล้ว **ผู้ใช้ทุกคนจะอัปเดตไม่ได้เลย** — เคยเกิดขึ้นมาแล้วจริงใน v009 และหลุดไปสอง commit กว่าจะเจอ

`verify-manifest.js` จึงแฮชจาก git blob ไม่ใช่ไฟล์ในเครื่อง และเช็คด้วยว่าไม่มีไบต์ CR ปนอยู่

### ขั้นตอนออก patch ใหม่

ไม่มีระบบอัตโนมัติ (ตั้งใจ เพราะไม่มี backend ให้รัน) ทำด้วยมือทุกครั้ง:

1. เทียบข้อมูลปัจจุบันในเกมจริง (ค่าพลัง, การ์ดใหม่, เมตา) กับสิ่งที่ฝังอยู่ในแอป — ปกติทำผ่าน Claude ช่วยหาข้อมูล/ตรวจสอบ
2. เขียน diff เป็นไฟล์ `patches/{version}.json`
3. เพิ่มรายการใน `manifest.json` โดยใช้ SHA-256 **ที่สคริปต์สร้าง patch พิมพ์ออกมา** ห้ามพิมพ์เอง
4. `git add` แล้วรัน `node verify-manifest.js` — ต้องขึ้น `ALL CHECKS PASSED` เท่านั้น
5. รัน `node --test` ให้ผ่านครบ
6. ทดสอบในเบราว์เซอร์จริงว่าอัปเดตจากศูนย์แล้วไล่ patch ครบทุกตัวได้
7. Commit + push

> เวลาตรวจว่า patch ใช้ได้จริง ให้เช็คกับ **ของที่เผยแพร่จริง** ไม่ใช่ไฟล์ในเครื่อง — `node verify-manifest.js --remote` จะดึงไฟล์จาก raw.githubusercontent มาแฮชเทียบให้ ใช้หลัง push แล้ว

ฝั่งแอปจะตรวจ hash ก่อนติดตั้งทุกครั้ง และมี snapshot ย้อนหลังให้ rollback ได้เสมอถ้า patch ผิดพลาด

**มี playbook แบบละเอียดทุกขั้นตอนอยู่ที่ [`docs/PATCH_UPDATE_PLAYBOOK.md`](docs/PATCH_UPDATE_PLAYBOOK.md)** — ใช้เป็น prompt ตั้งต้นได้เลยทุกครั้งที่จะสั่ง "อัปเดตแพตช์" ในเซสชันใหม่ ไม่ต้องอธิบายขั้นตอนซ้ำเอง มีทั้งวิธีเช็คว่าการ์ดปล่อยจริงหรือยัง (แหล่งข้อมูลเดียวเชื่อไม่ได้ — เคยเจอมาแล้วว่า status field ล้าหลังความจริงหลายวัน), สคริปต์ช่วยงานถาวรที่ `scripts/patch-tools/`, และรายการ gotcha ที่เจอซ้ำๆ ตลอดโปรเจกต์
